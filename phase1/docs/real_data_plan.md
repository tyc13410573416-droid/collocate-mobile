# 真实来源数据使用方案

## 结论

可以引入公开的真实世界脱敏数据，但“脱敏”不是唯一条件。每份数据都要同时确认：

1. 数据集来源可信；
2. 许可证允许比赛研究或二次分析；
3. 是否需要注册、培训或签署 Data Use Agreement；
4. 不把原始患者数据提交到公开仓库、截图或前端页面；
5. 不把真实数据发送到尚未确认合规边界的外部模型 API。

## 推荐数据层次

### 第一优先级：MIMIC-IV / MIMIC-IV-Note

- 来源：PhysioNet；真实临床数据，已做去标识化。
- 适合：检验指标、参考范围、时间序列、临床文本结构化测试。
- 限制：需要注册、完成培训并接受使用条款；不是直接可用的中文检验单图片。
- 用法：只提取必要字段，转换成项目内部的 `report_id / indicator / value / unit / status / source_id` 结构。

### 第二优先级：eICU-CRD

- 来源：PhysioNet；真实去标识化 ICU 数据。
- 适合：检验指标和用药核查的离线测试。
- 限制：需要按平台要求申请使用；字段和中文业务表达需要映射。

### 第三优先级：NHANES 或其他官方公开健康调查数据

- 适合：验证数值清洗、单位统一、异常分布和图表。
- 限制：通常不是完整的“检验单”或临床文本，不能单独证明报告 OCR 和多跳推理能力。

### Kaggle 数据集

可以作为补充，但下载前必须记录：数据集名称、原始来源、许可证、下载日期、是否真实/合成、是否需要署名。许可证不清楚、来源不明、包含可识别信息的数据不要使用。

## 本项目的建议组合

| 用途 | 数据 | 是否进入网页 Demo | 是否进入仓库 |
| --- | --- | --- | --- |
| 页面演示 | 中文合成报告 R001-R003 | 可以 | 可以，明确 `synthetic=true` |
| 清洗与图表 | MIMIC/eICU/NHANES 的必要字段 | 不直接展示原始记录 | 只放脚本、字段样例和统计结果 |
| 真实接口联调 | 经过字段最小化的本地测试副本 | 仅在授权环境 | 不提交原始数据 |
| OCR/图片入口 | 自制合成图片或获得明确授权的公开样例 | 可以 | 只放允许再分发的样例 |

## 转换后的统一字段

```json
{
  "report_id": "PUBLIC-DEMO-001",
  "synthetic": false,
  "source": "MIMIC-IV",
  "license_note": "按 PhysioNet 使用条款",
  "modality": "table",
  "indicator_code": "ALT",
  "value": 68.0,
  "unit": "U/L",
  "ref_low": 0.0,
  "ref_high": 40.0,
  "status": "high",
  "source_id": "PUBLIC-MIMIC-001"
}
```

## 组内下一步

1. 万嘉宜先确定要用的公开数据集和许可证，建立数据资产台账；
2. 汤永超写字段转换和清洗脚本，不保存原始患者文本；
3. 赖芷炫只接收转换后的最小字段或合成样本，先验证 `parse_report → query_reference → check_interaction`；
4. 网页继续使用合成中文案例，避免演示时暴露真实患者信息；
5. 文档中明确区分“真实来源脱敏数据用于验证”和“合成数据用于可复现演示”。
