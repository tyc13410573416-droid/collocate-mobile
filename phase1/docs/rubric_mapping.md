按截图中可见的团队评审结构，前端不只展示结果，还要让评委能看见创新、应用价值、完整性和答辩证据。

| 评审维度 | 页面证据 | 当前状态 |
| --- | --- | --- |
| 创新性 40% | 图片/PDF 多模态入口、双路召回与重排统计、知识库抽取与人工校验证据、知识关联网络弹窗 | 已做合成数据占位，真实字段待后端接口冻结 |
| 应用价值 35% | 检验报告输入、当前用药输入、用药核查警示卡、来源和参考范围 | 已做合成演示逻辑，不输出诊断或剂量建议 |
| 完整性与可展示性 15% | R001/R002/R003 快捷案例、加载状态、错误提示、免责声明、可点击引用、调用链 | 已完成并通过本地接口验收 |
| 答辩表现 10% | 分步骤 Agent 时间线、关系网络按钮、请求编号、技术证据标签 | 已做前端演示壳，后续可替换为真实 trace_log |

## 需要后端确认的字段

```json
{
  "warnings": [{"drug": "...", "risk": "...", "source": "..."}],
  "retrieval": {
    "vector_hits": 10,
    "keyword_hits": 5,
    "reranked": 3,
    "sources": [{"title": "...", "score": 0.92}]
  },
  "trace_log": [{"tool": "parse_report", "status": "done", "elapsed_ms": 120}],
  "graph": {"nodes": [], "edges": []}
}
```

当前 Mock API 已返回 `warnings`、`retrieval`、`knowledge_evidence` 和 `graph`，便于前端先完成演示；接入真实 Nexent 后，把这些字段替换成赖芷炫和万嘉宜确认的正式 Schema。
