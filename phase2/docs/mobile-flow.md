# 移动端分步解读

2026-11-25：手机与窄屏（宽度不超过 820px）采用输入和结果两个视图，电脑端保留原双栏。

- 初次打开只显示输入；生成按钮固定在手机底部。
- 点击生成立即切换到加载视图，请求完成后从结果顶部显示门控。
- 返回重新输入会保留文本、性别、用药、样本以及浏览器中已选择的图片。
- 请求中暂时禁用返回，避免结果和输入错配；失败后可直接重试或返回修改。
- 数值卡片在移动端先于长摘要显示；原始图片可展开查看，逐项人工核对、追问、来源与审计仍可使用。
- 原始控件通过 DOM 移动复用，不复制表单、不改变证据判定、不把真实失败切换为演示数据。
- 页面刷新后重新开始；不会将报告图片或文本另存到浏览器持久存储。

## 验证

`mobile-flow.browser.js` 在 320、390、768、820、821、1024、1440px 验证输入/结果隔离、加载、四类门控视图、返回保留、性别追问、错误重试、无横向溢出和电脑双栏。

`mobile-image-review.browser.js` 使用实际脱敏图5，调用真实 OCR 与核查接口；验证移动端人工确认 ALT=16 IU/L、缺性别继续复核、测试补充“男”后重新核查、可点击来源、原始 OCR 不被修改、原图与所选文件保留。通过仅覆盖已勾选 ALT，并不表示整份检验单通过。

`capture-mobile-flow.browser.js` 从已发布的 GitHub Pages 页面导出分步交互截图。真实照片流程截图来自同版前端及本机真实服务，详细图注随截图提供。
