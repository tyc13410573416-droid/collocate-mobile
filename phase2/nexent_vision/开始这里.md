# MedTrace 图片理解接入包（Nexent v2.8.1）

图片 → Nexent 附件存储 → Agent 调用 `analyze_image` → 视觉模型完整转录 → 现有 `parse_report / query_reference / evidence_gate` → 网页。

这条路径不走 Unstructured 文档 OCR，不需要补装 yolox、Tesseract 或重建 data-process 大镜像。前提是 Nexent 主服务和 MinIO 正常，并有可用的图片理解模型。

本包没有模型密钥或现成公网后端。目前仍未接通真实视觉服务，自动测试使用模拟服务，不能算真实图片识别验收。

## Nexent 同学要完成的三步

1. 在“模型配置”添加“图片理解模型”，填入已有账号的真实模型名、URL、API Key，通过连通性验证并选为可用模型。使用已有免费额度或本地模型，本包不会开通付费服务，也不假设 GLM-4.7 文本模型能读图。
2. 安装下面的完整转录提示词。默认图片工具偏短摘要，中文还有“200字以内”要求，密集检验单可能漏行。
3. 给图片 Agent 启用内置 `analyze_image` 和已有 MCP 工具，把同目录 `agent-image-system.md` 合入系统提示词，保存并发布 Agent。可使用独立图片 Agent，保留原文本 Agent。

在部署 Nexent、能执行 Docker 的 Windows 电脑，解压后进入 `MedTrace` 根目录：

```powershell
& .\phase2\nexent_vision\install-prompts.ps1 -Container nexent-runtime
```

脚本自动探测容器内 SDK 路径，先备份原始中英文提示词，再只复制两份小 YAML，并重启指定 runtime 容器以清除缓存。不下载镜像。原始备份保存在 `phase2/nexent_vision/backups/`。

容器名不同就修改 `-Container`。`-SkipRestart` 可以只复制、随后自行重启。容器重建会恢复原文件，需要重跑脚本或将两份 YAML 持久挂载到探测出的真实路径。源码部署则修改对应 SDK 提示词并重启实际服务。

脚本已检查 PowerShell 语法，但汤同学电脑没有 Nexent/Docker，尚未在真实容器执行。

## 启动 MedTrace 后端

包中包含网页和 Python 后端源代码。推荐 Python 3.11，依赖见 `phase1/requirements.txt`。在项目根目录配置真实值：

```powershell
$env:NEXENT_BASE_URL = 'http://实际Nexent网关地址/api'
$env:NEXENT_IMAGE_AGENT_ID = '实际数字AgentID'
$env:NEXENT_IMAGE_PROTOCOL = 'v2.8.1'
$env:IMAGE_ALLOWED_ORIGINS = 'https://tyc13410573416-droid.github.io'
# 需要授权时在本机环境设置 NEXENT_API_KEY，不写进网页。
python phase1/app.py
```

`.env.example` 不会自动加载。API 根地址应能同时访问 `/file/storage` 与 `/agent/run`，带 `/api`，不要填某个不提供全部路由的内部端口。

打开 `http://127.0.0.1:5050` 测试。存储接口若不返回 URL，配置 `NEXENT_ATTACHMENT_BUCKET` 为真实 MinIO 桶名，后端不会猜测。

GitHub Pages 需要浏览器能访问的 HTTPS MedTrace 后端。上线后展开共享页“关于本演示”，填写“图片识别后端地址”，保存并检查连接。地址只保存在本机浏览器，模型密钥仍在服务端。连接检查成功不代表识别已验收。

## 验收

不传图片时仅检查配置格式，不调用模型：

```powershell
python phase2/scripts/check_image_link.py
```

明确传图片才实际调用 Agent/视觉模型：

```powershell
python phase2/scripts/check_image_link.py --image '图2.png' --gender 未知 --expect GLU=16.1 --expect CRP=16.0
```

期望值仅用于已知图2的验收，不会写入识别结果；缺值或读错会失败。还要测试新图片、凝血单小数点、手机长图、缺性别后补充重提、模糊图复核、模型断开后不显示旧结果。

当前原生图片通道支持 JPG/PNG/WebP。PDF 可预览，识别前需导出为图片。

## 接口约束

代理按 v2.8.1 官方 `/api/file/storage` 与 `/api/agent/run` 协议传图；按 `answer_phase=delta/complete` 汇总根 Agent，忽略子 Agent 提前输出。观察到本次 URL 的真实 `analyze_image` 调用才接受结果，不能只在最终 JSON 中声称已调用。

最终 JSON 保留六个门控字段和三个挂载点，额外返回 `image_transcription={raw_text,readable,uncertain_fields}`。未确认读数不能 pass。转录以纯文本展示，不转发内部思考，不把自报置信度当作校准准确率。

官方依据固定提交：`30c5168452440dcf66c6785e1f478f9d2b4d3f4d`（v2.8.1），涉及 `analyze_image_tool.py`、`observer.py`、`file_management_app.py` 和 `conversationService.ts`。

旧 v1.8 可显式选择 `NEXENT_IMAGE_PROTOCOL=v1.8`，不具备 v2.8 的视觉调用检查，不能作为图片模型已运行的证据。
