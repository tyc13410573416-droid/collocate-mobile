# 人工核对与逐项来源关联

图片出现 `review` 后，可以点击“手动核对数值”，逐项检查读数、单位及不等号，勾选确认后提交。后端根据新的输入再次执行单位标准化、参考区间查询和三态门控；浏览器不会直接把状态改成通过。

“补充缺失信息”会引导填写性别或采样条件。缺性别的原始识图结果提供男女快捷按钮并重新提交；已经人工核对过的读数可保留，补充性别后直接重新核查。非空腹血糖不会套用当前空腹参考条目。

每个指标旁都有对应来源按钮：悬浮显示该指标的知识库摘要，点击打开详情，手机端同样可点击。当前 34 条知识库没有随附完整标准原文和页码，详情已明确说明；不能把摘要写成原文逐字引用。来源编号逐项分配，同一标准下的不同指标不会混用同一段摘要。

人工核对结果只覆盖用户勾选的项目，未选项目及原图其他未识别项目仍需核对。原始转录文字、不确定项、用户提交前后的数值和单位均保留在结果与审计轨迹中。人工确认不等于医疗专业人员确认，`pass` 不表示整份报告正常。

接口：`POST /api/review-image`，提交 `review_token`、`lab_results`（每项 `abbreviation/value/unit/value_comparator/confirmed`）、`gender`、`report_conditions` 和 `scope_confirmed`。令牌仅针对当前原图结果，有效期约 15 分钟；过期需重新上传。客户端不能传入新指标、来源或门控结论替换后端规则。

验证：

```powershell
python -m unittest phase2/tests/test_image_review.py phase2/tests/test_local_image.py phase2/tests/test_image_handoff.py
```

`phase2/tests/image-review.browser.js` 使用真实脱敏肝肾检验单验证图片识别、逐项确认、缺性别拦截、补充性别重算、单位标准化、逐项来源、原始 OCR 保留与多尺寸布局。测试补充的性别是交互测试输入，不代表原始样本患者的真实信息。
