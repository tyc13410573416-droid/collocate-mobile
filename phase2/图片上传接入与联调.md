# 图片上传接入与联调

## 当前范围（2026-11-23）

前端选择真实 JPG/PNG/WebP/PDF（单份 ≤10 MB）→ Flask 后端代理 → Nexent 附件存储 → Agent。
OCR 仍由 Nexent 负责，后续复用已有 MCP 工具，不增加浏览器 OCR 或改写门控规则。

队友目前反馈镜像源损坏，没有可用 Nexent 地址与 Agent ID。
**真实 OCR 尚未验证、尚未上线。** GitHub Pages 目前只提供本机文件预览与明确标注的预置样本演示。
不能因为“附件上传成功”就宣称“图片分析成功”。

## 协议依据

已核对 [Nexent v1.8.0 官方源码（固定提交）](https://github.com/ModelEngine-Group/nexent/tree/3ed8134a234c11ba6d3dde7f835f8c9b82ff6a88)：

- `backend/apps/file_management_app.py` 的 `POST /api/file/storage`：multipart 字段 `files`，`folder=attachments`，读取 `results[0].success` 与 `object_name`。
- `frontend/services/conversationService.ts` 和 `backend/apps/agent_app.py` 的 `POST /api/agent/run`：JSON 中传 `query`、`agent_id`、`minio_files`（`object_name/name/type/size`）。
- `backend/services/agent_service.py`：SSE `data: {...}`；最终结果事件为 `type=final_answer`，正文在 `content`；失败为 `type=error`。

**这是 v1.8 协议适配，不能假定所有 Nexent 版本兼容。** 最新 develop 文件上传接口已有变化；恢复后先确认队友版本与网关前缀，再实机核对这两个接口。不要将旧项目 `/v1/analyze` JSON 适配器当成 Nexent 原生传图接口。

## 队友恢复服务后需要提供

1. 本机/部署后端可访问的 Nexent API 根地址（例如 `http://服务器:端口/api`）。
2. 能处理附件并调用 OCR、parse_report、query_reference、evidence_gate 的 Agent ID。
3. 实际部署版本；需要授权时，在后端环境中配置 Token。
4. 确认 MinIO、data-process/OCR 可用；Agent 最终输出完整项目 JSON，不能只有 Markdown 解读。

Agent 必须输出既有字段：`answer`、`lab_results`（或 `items`）、`decision_gate`、`confidence`、`evidence_status`、`conflicts`、`next_action`、`source_versions`、`citations`、`trace_log`、`metadata`。
`decision_gate` 仅 `pass/review/abstain`；缺性别、冲突、低置信度均为 `review` 子类。通过不表示医学正常。
前端不会依据普通文字、自行猜测数值或补造医学结论。

## 本地启动

`.env.example` 只作配置示例，**Python 启动不会自动读取 .env**。PowerShell 中设置实际环境变量：

```powershell
$env:NEXENT_BASE_URL = 'http://服务器:端口/api'
$env:NEXENT_IMAGE_AGENT_ID = '实际数字ID'
$env:NEXENT_IMAGE_PROTOCOL = 'v1.8'
# 按部署要求设置后端 NEXENT_API_KEY，禁止写入 docs 或聊天截图。
python phase1/app.py
```

访问本机 `http://127.0.0.1:5050`。`GET /api/image-status` 仅检查配置，不代表 OCR 已可用。
选择一份新图片→点击生成：页面按真实服务事件显示“上传中→附件已上传→已交给 Agent→收到结构化结果”。
图片请求不会回退到示例数据，断网/超时/解析失败后保留所选文件，可直接重试。

## 免费共享网页的接法

GitHub Pages 无法运行 Python 代理。服务恢复后仍需一个浏览器可访问的 HTTPS 后端，或者将前后端一起部署。
现有 Dockerfile 已包含 `docs` 静态资源；容器须注入上面的服务端环境变量。不能把 API Key 写在 Pages 中。

如果继续使用 Pages 前端，需在 `docs/index.html` 的公开配置中设置 **自己的后端** `imageApiBase`（不含 `/api`）：

```js
window.MEDTRACE_CONFIG = { mode: "demo", imageApiBase: "https://你的后端域名" };
```

后端设置 `IMAGE_ALLOWED_ORIGINS=https://tyc13410573416-droid.github.io`，严格匹配来源。
`mode: "demo"` 保留合成文本样例演示；自行上传文件单独走图片代理，不能命中预置图片结果。
公网代理没有项目用户登录机制，只适合受控比赛演示；后续开放给更多人使用时需增加服务端鉴权与额度限制。

## 我们自己的前后端接口

`POST /api/analyze-image`：multipart `file`、`gender`、`raw_text`（可选补充）、`medications`。
不接受客户端提供上游地址或 Token；不把原始文件名传给 Nexent，不把图片内容记录到访问日志。
代理不主动持久化文件；上传后的附件由 Nexent/MinIO 保存，清理和保留周期由平台管理员设置。

参数/未配置错误返回 JSON + 4xx/503。通过检查后返回 `application/x-ndjson`：

```json
{"type":"stage","stage":"uploading"}
{"type":"stage","stage":"uploaded"}
{"type":"stage","stage":"agent_submitted"}
```

随后只会有 `{"type":"result","result":{...完整门控JSON...}}` 或 `{"type":"error","error_code":"...","error":"..."}`。
流式阶段的失败也可能使用 HTTP 200，必须读取最后的 `result/error`，不能只看状态码。
不向浏览器转发 Agent 内部思考文本或可能含密钥的底层异常。

## 验证

```powershell
python -m unittest phase2/tests/test_image_handoff.py
```

此测试启动本地假 Nexent HTTP 服务，核对真实 multipart 文件字节、返回附件标识、性别与用药转交、SSE 最终 JSON，以及未配置/断网/非结构化结果/错误不回退示例。
**测试覆盖传输与接口契约，不证明真实 OCR 能识别医学检验单。**

实机验收还需：新图片提取值与原图核对；图2 GLU=16.1、CRP=16.0；缺性别触发 review 并保留同一文件重提；长图与 PDF；OCR 不可用时不出现假结果。
